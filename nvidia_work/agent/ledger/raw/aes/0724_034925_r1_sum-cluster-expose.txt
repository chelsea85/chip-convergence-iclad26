An elegant optimization is applied to `tlul_cmd_intg_chk.v` using the **[rtlscout-cutpoints]** playbook strategy. 

### Ledger
- **Transform Applied**: `[rtlscout-cutpoints]` (Declare named intermediate wires with explicit widths at logical boundaries to simplify complex compile-time constant-expression slices and assist Yosys/ABC partitioning).
- **Exact Cone Touched**: `tlul_cmd_intg_chk` module internal slice extractions and function calls.
- **Changed Signals**:
  - `chk_data_intg`: original (inline slice expression) -> new width 7, unsigned.
  - `data_intg`: original (inline slice expression) -> new width 7, unsigned.
  - `data_val`: original (inline slice expression) -> new width 32, unsigned.
  - `err_bit`: original (inline slice expression) -> new width 1, unsigned.

### Optimization Rationale
The original code contained extremely complex, nested ternary and arithmetic index expressions for slicing the wide `tl_i` bus. While these evaluate to constants at compile time, their complexity often confuses synthesis front-ends (like Yosys), leading to sub-optimal gate mapping, redundant logic, or unnecessary multiplexer structures. By pre-calculating these slices into clean, parameter-derived `localparam` constants and declaring explicit intermediate wires at logical boundaries, we eliminate synthesis confusion and allow the tool to directly wire the bits, significantly improving timing and area.
